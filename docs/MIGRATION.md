# 迁移方案：从 WPF 到 Go + Electron + React

目标是让同一项运维操作在新版得到可解释、可回退的结果，**不是翻译 XAML 或把旧目录复制一遍**。下面“旧版”指编写时核对的相邻工作树：分支 `main`，提交基点 `f9e83d6`，另有未提交的代码、测试、脚本与离线清单变更。该提交号不能单独重建本次看到的工作树。本文未运行旧版全量测试、未接触实际用户数据库、未连接服务器。

引用的旧文件以相邻目录名 `远程安装应用` 为前提，只作迁移取证；新项目发布、构建和运行不应依赖该目录存在。若旧 README、手册与代码冲突，记录差异并以当前实现/测试和明确认可的产品行为为准，不直接把旧说明写成新版承诺。

## 1. 冻结基线，而不碰旧版

- 在 P0 由维护者确认纳入哪些未提交更改，记录提交、选定文件的差异/指纹及资源清单版本。尤其核对 `DefaultPackageResolver`、旧库补列逻辑、ARM64 清单与实际包；不能把缺失文件当成“已验证齐全”。排除生成目录、签名密钥、真实日志、账号资料。保留旧版可运行安装包的版本和校验值作为试点回退依据。
- [应用配置源文件](../../远程安装应用/Scripts/app-configuration.json) 定义 12 个 ID、对应 10 个界面应用家族：MySQL、MariaDB、Redis、Nginx、Elasticsearch、RabbitMQ、Mosquitto、Consul、Traefik、JDK（8/11/17）。[旧构建映射](../../远程安装应用/RemoteInstaller/RemoteInstaller.csproj) 把配置映射到输出 `Scripts/`；实际脚本和资源在 `RemoteInstaller/Scripts/` 的各应用目录，而非概括性的两套 Linux/Windows 根目录。新版应显式记录 ID → 大小写准确的目录名。
- 建三类可提交的小样本：① 脱敏脚本行与结果预期；② 微型假包、索引与 SHA-256；③ 可重复生成的合成 SQLite/测试凭据。旧测试有会访问默认用户库的路径，迁移回归必须注入临时目录。旧报告只作旧版证据，不继承其通过状态。

## 3. 行为对照：不能只比较返回码

旧依据：[解析器](../../远程安装应用/RemoteInstaller/Services/Operations/ScriptProtocolParser.cs)、[状态测试](../../远程安装应用/RemoteInstaller.Tests/ApplicationStatusNormalizerTests.cs)、[决策实现](../../远程安装应用/RemoteInstaller/Services/Operations/OperationDecisionPolicy.cs)。把输入和预期结果做成两个语言共用的夹具，不在测试里通过真正的卸载来制造失败。

| 场景 / 输入证据 | 应得到的业务结论 |
|---|---|
| 文本 `PROGRESS:Installing:40`；等价 JSON 进度；未知普通行 | 前两者为同阶段 40% 进度，普通文本作日志，不冒充结构化事件。覆盖混合换行、分片到达、超范围进度和无效 JSON |
| 检测成功，应用不存在 | 检测任务完成，应用为“未安装”；连接/权限失败则是“检测失败/状态未知”，不能互换 |
| 脚本退出异常，但安装后复查已安装 | 完成并告警；已装未运行与已装运行分开显示 |
| 脚本成功退出、复查未安装 | 仅退出码 0 不够，应失败；若脚本同时有 `SUCCESS` 阶段与可归一化的安装证据，按旧策略可“完成并告警” |
| 卸载后仍运行或仍安装；反之只留服务定义/配置 | 前者失败；确认不再安装且仅残留时完成并告警；确认不存在且无残留才可完成。另核对 `keepData` 的保护对象；仅传入参数不证明保留成功 |
| 卸载脚本异常/只输出错误，独立复查也失败，缺少可信的否定证据 | 新版标“中断/待复查”，不可判完成；覆盖[旧复查异常分支](../../远程安装应用/RemoteInstaller/Services/InstallerService.cs)将默认布尔值误作“不存在”的边界。只有恢复连接并得到可信状态才能更新结论 |
| 只有配置 `PORT`、RabbitMQ 管理地址等；或有实际监听 `PORT_LISTENING` / 服务运行证据 | 配置值不单独判运行；监听、进程或活动服务证据按旧归一化规则处理 |
| 两主机多应用；其中一个失败、任务取消或终态后又来进度 | 验证 M04 调度顺序与并发，失败隔离；取消单独报告、不重放，终态不倒退。主机刷新与底层操作队列分层测试 |

**有意修正：** 旧策略层有 `HasWarning`，但旧执行器构造部分最终结果时固定传 `false`。新版将告警随最终状态持久化并显示，用夹具固定“策略 → 事件 → UI/历史”全链路，不复刻丢告警现象。新加的主机指纹确认、跨平台凭据补录和可见的中断状态也要出现在用户迁移说明中。

**卸载权限与数据边界（M03/G3）：** 按应用、远端平台、保留模式登记允许操作的服务、包、配置和目录，列出同机非目标服务；来源/归属不明则在远端变更前阻止。旧 [Mosquitto Linux 卸载](../../远程安装应用/RemoteInstaller/Scripts/Mosquitto/uninstall_linux.sh) 会清理持久化目录，不能仅靠传 `keepData` 承诺保留；旧 [MySQL Linux 卸载](../../远程安装应用/RemoteInstaller/Scripts/MySQL/uninstall_linux.sh) 的包匹配也包括 MariaDB。新版先修正影响范围或禁用对应组合，不原样启用。验收用隔离快照预置可读取的持久化消息/测试库及一个非目标服务，对照操作前后数据标记、包清单与非目标服务可用性。未证明保留能力时拒绝“保留数据卸载”，不得静默改为清除数据。

## 4. 迁脚本、配置与离线包

**明确安装来源（M02/M09）：** 保留旧版已证明可用的显式在线能力，而不是把它与“离线缺件自动联网”混为一谈。按应用 × 远端系统建立能力表，由 P0 初列、P4 实测，默认仅显示已验入口。旧 [安装来源 UI](../../远程安装应用/RemoteInstaller/ViewModels/InstallConfigViewModel.cs) 与 [Redis 脚本在线分支](../../远程安装应用/RemoteInstaller/Scripts/Redis/install_common.sh) 是两种不同强度的证据：

| 应用（十个家族） | 显式在线的迁移决策与验收 |
|---|---|
| MariaDB、Mosquitto | 保持仅离线，缺件时停止；不因网络可用而放开在线入口 |
| Redis | 保留有实现且实测通过的远端组合；确认来源后测试显式在线成功/仓库不可达。对同一组合另测离线缺包，断言没有在线请求 |
| MySQL、Nginx、Elasticsearch、RabbitMQ、Consul、Traefik | 旧 UI 可展示在线选项；分别查对应脚本、受信来源和真实目标。经证实的组合移植并验收；只见入口未证实执行链的标“待验/不开放”，不能声称旧实用能力已覆盖 |
| JDK 8/11/17 | 市场中的版本逐一核实在线来源；独立 JDK 文件夹上传模式始终按本地输入，不提供在线选项 |

客户端离线可启动不等于远端显式在线安装无需网络。没有用户主动选择、来源未确认、平台不支持时，不从离线模式切换。

1. 从源码与应用配置建立目录映射，先迁小型脚本/参数模板及依赖的同目录脚本，再迁资源清单。版本目录优先；Linux 优先发行版入口，再到兼容 `_linux.sh`；Windows 按 `_windows.ps1` 解析，对实际存在的旧版变体做夹具。不能只带入口遗漏 `*_common.sh`。保留复合后缀 `.tar.gz`/`.tar.xz`、Unix 权限/换行；不要从旧 `bin` 或 `publish` 采样。[解析器测试](../../远程安装应用/RemoteInstaller.Tests/ScriptResolverTests.cs)
2. 基础安装包只带小脚本和元数据。旧工作区 `RemoteInstaller/Scripts` 此前实测约 **5.11 GiB**，数值是本地快照，不是新版体积预算。按应用、版本、远端系统/版本/架构分包；旧清单和实体分别验（路径、大小、SHA-256、依赖、索引），发布时附来源、许可与受信清单。旧 ARM 清单记录 718 个逻辑条目、349 个不同 SHA-256、12 个内嵌 APT 索引；**不是**“已测试了 718 个安装场景”。包授权再分发与文件完整性分别确认。
3. Ubuntu 22.04/24.04 ARM64：MySQL、MariaDB、Redis、Nginx、RabbitMQ/Erlang、Mosquitto 各用对应 `arm64/Packages`。检查非空索引、每个 `Filename` 与实体匹配、架构及依赖全；不把旧 amd64 平铺目录或在线下载作为兜底。Consul、Traefik、Elasticsearch、Temurin JDK 走对应归档与解压依赖。界面配置的可选版本不必然等于资源实物版本，未匹配不得冒充用户选定版本。
4. CentOS 7 ARM64：上述六类系统包缺已验证 EL7 AArch64 依赖闭包，预期结果是明确拒绝；另四类归档按旧支持范围，先检查目标机解压工具。AMD64 保留经样本验证的旧目录例外（如部分 Ubuntu 平铺资源）；Windows Server 按已有 Windows 入口/资源逐应用核对，不能因某 Linux 组合成功就默认 Windows 成功。
5. P3 只带一个可逆组件做纵向验证；P4 再逐家族补齐。每种发布组合记：操作、应用/真实资源版本、远端版本/CPU、清单哈希、预检、安装后复查、卸载后复查、证据与结果。分列“元数据符合”“逐文件校验”“真机闭环”。旧 [ARM 实机记录](../../远程安装应用/docs/arm-smoke-validation-2026-06-27.md) 仅证明当次只读识别链路，不能替代新版安装闭环。

## 5. SQLite 数据迁移和凭据补录

在新版选择「设置 → 旧版数据 → 选择快照并预览」。0.1.0 导入六表允许的元数据，保留旧记录之间的关联。导入后需重新录入主机认证、私钥路径、仓库和代理设置。旧日志正文、错误详情及部署命令继续从旧版或受控备份查阅。

**旧事实：** 默认库在 `%LOCALAPPDATA%\RemoteInstaller\data.db`，部分部署还有程序目录旧库。旧 `DatabaseService` 初始化会建表、补列、写种子并清理废弃项，**不能**用它打开源库做探测。`GetAllTasks()` 只取最近 100 条，不能用 UI 列表当全量导出。旧凭据实际使用 Windows DPAPI `CurrentUser`，不能按文档里笼统的“AES-256”假设解密。某些仓库/代理设置原来按普通字段存储，迁移时同样是机密。

| 旧表 / 资产 | 导入规则 | 对账依据 |
|---|---|---|
| `hosts`、认证字段与密钥路径 | 保留 ID、名称、分组与已记录的远端系统、版本和 CPU。缺列时由重新探测补全。首次连接需重新确认指纹和录入密码，或通过本机选择器定位私钥 | 核对数量、ID、分组与架构。导入的主机标记待录入凭据 |
| `tasks`、`logs`、`install_history` | 读取原始表并保留可关联的主机和任务、操作、时间与状态。历史正文和错误详情标记省略。旧任务只进入历史记录，运行中的旧任务标记为中断 | 用超过 100 条的样本核对总数、状态和关联。旧时间保留源文本，缺引用时报告孤儿记录 |
| `settings` | 明确可迁移键和类型，迁连接/界面配置；`RepositoryToken`、`ProxyPassword` 不进入普通 KV 或报告。仓库/代理/缓存绝对路径重新验证，不逐项盲拷贝 | 逐键区分“迁入/需重设/未知跳过”；断开密钥库时不写明文，汇总不含真实值 |
| `custom_apps` | 保留 `app_key`、类型、启用/排序和用户定义路径；与新版内置种子按稳定键去重。用户停用不因重建种子被恢复。导入定义不执行命令 | 三种部署类型、禁用与自定义条目各有样例；同名不同 ID/历史遗留记录显示冲突，不覆盖用户编辑 |

**导入流程（P5，先模拟、再试点）：**

1. 用户明确选择源，记录来源标识/版本；先退出旧版或按 [SQLite Backup API](https://www.sqlite.org/backup.html) 得到一致快照。存在 WAL 时不可只复制正在写的 `data.db`，也不要删除用户的 `-wal/-shm`。源库/原备份不写，临时快照与带敏信息的报告限当前用户并制定清理时机。
2. 对快照检查完整性、存在的表/列、枚举和引用，确认缺列兼容策略；生成只读预览：各表计数、待补凭据、坏关联/未知类型、冲突和预计占用。用户可选择只迁主机、其余延后；取消预览不留下新主机或凭据。
3. 导入保存 `(来源命名空间, 旧表, 旧主键) → 新 ID` 和行摘要。再次导入时比较上次结果、当前源和当前新版数据。无变化则复用，只有源更新时可在预览后接受更新。双边编辑冲突需先处理，源端缺失的记录在报告中显示。对于接受更新的主机，连接目标变化后需要重新录入凭据和核对指纹。
4. 核对范围后执行导入。新版在同一 SQLite 事务保存允许的行、映射和批次记录，完成对账后提交。报告显示已导入和跳过项。遇到冲突、源预览失效或对账失败时回滚，由操作者重新预览。
5. 导入失败时查看报告并重新预览。操作已提交但窗口没收到结果时，同一来源再次导入会按映射与摘要识别已导入的行。需要迁移凭据的主机，在新版单独执行指纹核对和认证测试，然后按需存入该平台的凭据库。

## 6. 双轨验证、切换与回退

| 次序 | 可执行动作 | 继续 / 停止条件 |
|---|---|---|
| ① 离线回放 | 同一组脚本轨迹、状态样本、资源和旧库同时产生期望值与新结果；按 M01–M12 记录差异、负责人及处理决定 | 未解释的成功/失败差异、跨架构回退、源库被改、明文泄露均停止；正常的有意变更有说明与测试 |
| ② 只读影子 | 经授权在同一测试主机上比较旧/新版检测，或对照同份录制输出；按目标 OS/CPU 分列 | 主机识别、应用状态、配置端口/实际监听等语义一致。不给两套客户端同时下发修改同一主机的任务 |
| ③ 可逆试点 | 在可快照的授权环境，一次只让一版写目标，演练安装、卸载、保留数据、终端/传输和异常中断；准备旧安装包、原库备份与新版导入报告 | 通过相关 G1–G6 且有操作者确认；无真机、无资源、无签名身份都如实标“受阻”，不代填“通过” |
| ④ 切换 | 小批工作站安装新版；冻结旧版写操作，对最后一致快照做源/目标/试点基线三方比较并受控导入。同一主机 ID 的连接地址、端口、指纹逐项复核；不以总行数相等放行。保留旧安装包、旧库和资源，明确切换负责人 | 出现错误选包、凭据明文、严重终态误判、数据对账无法解释时停止扩量，进入回退 |
| ⑤ 回退 | 停止新版队列并记录未完成任务；先只读检查远端真实状态，再恢复旧客户端/旧库进入管理。不删除新库和审计证据，不强行把新版数据写回旧结构 | 桌面版本回退**不会撤销远端变更**；新增记录或变更另列手工对账。需要恢复某服务/配置时从测试过的备份单独审批执行，不能由客户端回退触发自动卸载 |

**迁移完成定义：** 准备发布的每个客户端组合有独立试装记录；承诺支持的每个远端组合与例外有测试或明确的未支持说明；旧数据可核对、旧版可回退、关键有意差异已对使用者说明。未获验证的平台、组件或恢复路径不宣称“全量迁移完成”。
